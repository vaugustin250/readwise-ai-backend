## 1. Executive Summary

An independent technical audit was conducted on the ReadWise AI repository following the reported completion of Remediation Phases 1 through 5. 

The audit confirms substantial structural improvements:
- **Authentication & Authorization** have been hardened: mock tokens are strictly rejected (HTTP 401), bcrypt password hashing is active, signed JWT access tokens are validated on protected routes, and guardian-to-child IDOR vulnerabilities are prevented (HTTP 403 Forbidden).
- **Alembic Schema Tracking** is operational with baseline migration `c594a069c6c0` tracking `users`, `child_profiles`, `assessments`, and `metrics`.
- **Automated Test Suites** pass completely: **17/17 pytest tests** (100%) and **9/9 Flutter tests** (100%) pass, with **0 static analysis issues** in `flutter analyze`.
- **Track A Empirical Benchmark** on the real ETDD70 eye-tracking dataset (Zenodo 13332134; 70 participants, 210 trials) was **successfully reproduced** using 5-Fold `GroupKFold` participant-level cross-validation (Logistic Regression: ROC-AUC 0.854 ± 0.061, Accuracy 79.0%; Random Forest: ROC-AUC 0.845 ± 0.044, Accuracy 72.9%).

However, the audit revealed critical operational and scientific boundaries that prevent unrestricted production release:
1. **Deployment Storage Ephemerality (Critical):** `render.yaml` does not configure a PostgreSQL service or provision `DATABASE_URL`. In cloud deployment on Render, the backend defaults to SQLite (`sqlite:///./test.db`), causing complete data loss across restarts and spins-down.
2. **Track B Multimodal Provenance (High):** Track B (reported ROC-AUC 0.967) relies on speech hesitation, phoneme stability, working memory, and phonological awareness features that were generated by sampling from Gaussian distributions conditioned directly on the ground truth diagnosis label (`is_dyslexic`). Track B represents an exploratory synthetic simulation rather than empirically collected multimodal patient data.
3. **Android Biometric Parity (High):** While native front-facing camera preview and microphone decibels are live, real-time computer-vision gaze tracking (iris/pupil coordinates) and on-device Whisper speech transcription are not running in Flutter; regressions are captured via tactile word tapping, and speech acoustic features use calibrated priors.

## 3. Detailed Audit Findings Ranked by Severity

### [CRITICAL] Finding 1: Cloud Deployment Defaults to Ephemeral SQLite Database
* **Severity:** Critical (Data Persistence & Security)
* **Location:** [`render.yaml`](file:///d:/dyslexia/render.yaml), [`backend_api/app/core/config.py`](file:///d:/dyslexia/backend_api/app/core/config.py#L9)
* **Description:** In `render.yaml`, the environment configuration specifies `ENVIRONMENT=production` and generates `SECRET_KEY`, but does **not** declare a managed PostgreSQL database or pass a `DATABASE_URL` environment variable. In `config.py`, `DATABASE_URL` defaults to `sqlite:///./test.db`. On Render's free/standard web instances, the local container disk is ephemeral: all registered guardian accounts, child profiles, screening assessments, and longitudinal metrics are permanently erased upon container restart, redeployment, or idle spin-down.
* **Evidence:**
  ```yaml
  # render.yaml (lines 7-15)
  envVars:
    - key: PYTHON_VERSION
      value: 3.10.11
    - key: PYTHONPATH
      value: .:backend_api
    - key: ENVIRONMENT
      value: production
    - key: SECRET_KEY
      generateValue: true
    # MISSING: DATABASE_URL referencing managed postgres
  ```

### [HIGH] Finding 2: Track B Multimodal Features Exhibit Generative Label Leakage
* **Severity:** High (Scientific Validity & Paper Publication)
* **Location:** [`scratch/train_master_screener.py:L15-L25`](file:///C:/Users/agust/.gemini/antigravity-ide/brain/d8181bbd-9047-44d3-b275-54478771f430/scratch/train_master_screener.py#L15-L25), [`notebooks/03_multimodal_fusion_xgboost_xai.ipynb`](file:///d:/dyslexia/notebooks/03_multimodal_fusion_xgboost_xai.ipynb)
* **Description:** The ETDD70 dataset contains exclusively eye-tracking recordings (70 subjects, 210 trials). In `train_master_screener.py` and the fusion notebooks, non-ocular features (`speech_hesitation_rate`, `speech_phoneme_stability`, `cognitive_working_memory`, `phonological_awareness_score`) are synthesized by sampling from normal distributions partitioned directly by `is_dyslexic = (df['class_id'] == 1)`.
* **Evidence:**
  ```python
  # scratch/train_master_screener.py lines 21-24
  df['speech_hesitation_rate'] = np.where(is_dyslexic, np.random.normal(4.2, 1.2, n), np.random.normal(1.6, 0.6, n)).clip(0.2, 8.0)
  df['speech_phoneme_stability'] = np.where(is_dyslexic, np.random.normal(-0.25, 0.35, n), np.random.normal(0.65, 0.25, n)).clip(-1.0, 1.0)
  df['cognitive_working_memory'] = np.where(is_dyslexic, np.random.normal(62.0, 14.0, n), np.random.normal(82.0, 10.0, n)).clip(30.0, 100.0)
  df['phonological_awareness_score'] = np.where(is_dyslexic, np.random.normal(55.0, 15.0, n), np.random.normal(85.0, 9.0, n)).clip(25.0, 100.0)
  ```
* **Impact:** The resulting cross-validation metrics (ROC-AUC ~0.967) reflect the separation programmed into the synthetic Gaussian generators, rather than empirical multimodal sensor fusion. In academic peer review, this must be explicitly characterized as a *simulated feasibility demonstration* rather than clinical validation of speech/cognitive biomarkers.

### [HIGH] Finding 3: Smartphone Sensor Extraction Relies on Tactile & Heuristic Fallbacks
* **Severity:** High (Functional Parity)
* **Location:** [`mobile/lib/screens/reading_assessment_screen.dart:L70-L84`](file:///d:/dyslexia/mobile/lib/screens/reading_assessment_screen.dart#L70-L84), [`mobile/lib/services/sensor_manager_io.dart:L133-L165`](file:///d:/dyslexia/mobile/lib/services/sensor_manager_io.dart#L133-L165)
* **Description:** 
  1. **Gaze Regressions:** The front camera renders a live preview, but no real-time computer vision (e.g. MediaPipe Face Mesh / pupil gaze vector) processes frames on Android. Backward regressions are detected only when the user or proctor manually taps backward on passage words (`_onWordTapped`).
  2. **Speech Telemetry:** The microphone records amplitude to drive a decibel VU-meter. However, speech audio is not transcribed on-device or streamed to Whisper during the screening POST; `speechHesitationRate` and `speechPhonemeStability` use default constants (`2.1` and `0.65`) unless modified by simulated timer ticks.
* **Impact:** Without explicit disclosure, evaluators may assume computer vision and acoustic phoneme analysis are operating autonomously from raw camera/mic hardware.

### [MEDIUM] Finding 4: Missing Request Idempotency on Assessment Submission
* **Severity:** Medium (Data Integrity)
* **Location:** [`backend_api/app/api/v1/endpoints/assessments.py:L242-L267`](file:///d:/dyslexia/backend_api/app/api/v1/endpoints/assessments.py#L242-L267)
* **Description:** `POST /api/v1/assessments/screen` unconditionally creates and commits an `Assessment` and `Metrics` record on every invocation. If a guardian experiences network jitter or rapidly taps "Finish Reading", multiple identical assessment trials are persisted into the child's longitudinal history.
* **Remediation:** Introduce an optional client-generated `idempotency_key` or debounce assessment submissions within a 60-second window.

---

### [LOW] Finding 5: Exception Masking on Database Persistence
* **Severity:** Low (Observability)
* **Location:** [`backend_api/app/api/v1/endpoints/assessments.py:L264-L266`](file:///d:/dyslexia/backend_api/app/api/v1/endpoints/assessments.py#L264-L266)
* **Description:** If `db.commit()` raises an exception during assessment recording, the error is printed to stdout and rolled back, but the endpoint proceeds to return HTTP 200 OK with the screening inference. The client assumes the assessment was saved, but subsequent calls to `/progress` or `/report` will not find the session.
* **Remediation:** Either propagate HTTP 500 or include a `persisted: false` status flag in `AssessmentScreenResponse`.

## 5. Machine Learning Metric Provenance & Scientific Validity

### Track A (Empirical Eye-Tracking Benchmark on ETDD70)
* **Data Source:** Zenodo 13332134 (Clinical reading trials from 70 participants: 35 dyslexic, 35 control; 210 trials total).
* **Validation Scheme:** Strict 5-Fold `GroupKFold` split grouped on `subject_id` (zero inter-fold subject leakage).
* **Audit Reproduction:**
  * **Logistic Regression:** ROC-AUC: **0.854 ± 0.061** | Accuracy: **79.0% ± 9.8%**
  * **Random Forest:** ROC-AUC: **0.845 ± 0.044** | Accuracy: **72.9% ± 4.9%**
  * **XGBoost:** ROC-AUC: **0.828 ± 0.065** | Accuracy: **75.7% ± 6.1%**
* **Scientific Verdict:** **Empirically Sound & Fully Reproducible.** Claims in Section V of the paper match verified code execution.

### Track B (Multimodal Intermediate Fusion Exploration)
* **Data Source:** ETDD70 ocular features + synthetic speech hesitations & cognitive metrics generated via `np.where(is_dyslexic, N(μ1, σ1), N(μ2, σ2))`.
* **Validation Scheme:** 5-Fold `GroupKFold`.
* **Audit Evaluation:** While `GroupKFold` separates subjects properly, the underlying non-ocular features were generated directly from the binary diagnosis label.
* **Scientific Verdict:** **Exploratory Simulation Only.** Must be explicitly reported as simulated multimodal augmentation. Under no circumstances should Track B be presented as clinical validation of smartphone speech or cognitive sensors.

## 8. Final Audit Verdict

### **VERDICT: READY FOR CONTROLLED PILOT**

#### Justification:
* **Why Not "Not Ready":** The application is no longer a mock prototype. Authentication, signed JWT tokens, guardian authorization, IDOR elimination, Alembic migration tracking, dynamic cognitive test batteries, database-backed progress histories, and empirical Track A model verification are all implemented, tested (100% pass rate), and functional.
* **Why Not "Ready for Production":** The production deployment on Render lacks persistent PostgreSQL configuration (defaulting to ephemeral SQLite), and the mobile app utilizes touch-guided regression tracking and simulated acoustic priors rather than automated on-device computer vision and Whisper ASR.
* **Controlled Pilot Suitability:** The system is in an optimal state for a **controlled educational pilot** where teachers or guardians supervise reading sessions, observe tactile word tracking, administer cognitive games, and evaluate generated educational intervention reports under adult consent.
